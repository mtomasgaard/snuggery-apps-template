# Setting up Finances

Paste this whole file into a coding-agent session that has this repository open — **your own
copy**, made with *Use this template*, never the template itself. The agent does the typing; the
person sitting at the keyboard does the parts only they can do (their bank sign-in, their
authentication app). Read it together before starting.

## What this app is

Finances is six panes — Overview, Owned, Spending, Cash flow, Savings, Transactions — built from
three kinds of number:

- **Accounts, balances and transactions**, read once a day from your banks through
  [Enable Banking](https://enablebanking.com), a licensed PSD2 account-information provider.
- **Fund units**, accrued from the standing transfers that bought them and priced at published
  NAV, because a fund platform is not a payment account and PSD2 cannot see it.
- **The things no bank reports** — the home, the cars, the loans against them — anchored to a
  value you know on a date you know, then moved by a published house-price index, a depreciation
  curve, or an amortisation schedule.

The copy you just installed holds **invented data**: a made-up household, generated by
`scripts/make_demo_finances.py` from a fixed seed. The app says so on screen, in a banner, and in
a visible "Example text" note. This guide replaces it with your own.

## Before you start

- You are working in **your** copy of this repository, not the template. If `gh repo view` shows
  the template's own name (`snuggery-apps-template`) rather than a repository you own, stop and
  make your copy first with *Use this template*.
- **Make that copy private, and check it before the first real run.**
  `gh repo view "$REPO" --json visibility -q .visibility` must print `PRIVATE`. This repository
  will hold your balances, your merchants and a year of your transactions. Git history cannot be
  un-published.
- Python 3.10 or newer (`python3 --version`).
- `gh auth status` should show you signed in. If not, `gh auth login` first.
- Set the repository once, and reuse it below:
  ```
  REPO=$(gh repo view --json nameWithOwner -q .nameWithOwner)
  ```

## Ground rules for the agent

- **The private key and the session ids are credentials.** They go into GitHub secrets and nowhere
  else. Never `echo` one, never write one into a file inside this repository, never paste one into
  a chat or a commit message.
- **The person does every sign-in.** The agent must not automate, watch, or store a bank password
  or an authentication code.
- If a step fails, stop and report the exact error text rather than working around it.

## Step 1 — see your own numbers before touching a bank

The banks are the slow half. Everything else needs no credential at all, so start there: it is the
fastest way to find out whether this app is worth the setup.

Open **`finances/assets.json`** and replace the example household with yours — the home's
`anchorValue` and `anchorDate`, the cars, the loans' `principal`, `startDate`, `termMonths` and
`nominalRate`. Every field is explained in the file itself. Then:

```
python3 scripts/finances.py --probe-assets
```

That prints every region and dwelling type the index offers, then values each of your assets and
loans so you can see the numbers before trusting them. Names are matched loosely, so `blokk` finds
`Blokkleiligheter`.

**If you are not in Norway**, the index does not cover you: set the home's `method` to `rate` with
an annual percentage you can defend, and write your reasoning in `note` — the app labels an
assumption as an assumption. `finances/NOTES.md` says what replacing the index would take.

Then open **`finances/holdings.json`** and put in what you hold: one entry per fund, with its
name, ISIN, the **units** you hold, what you have **paid in**, and `anchorDate` set to the day you
read those units off.

Then decide how the fund gets priced. `navSource: "manual"` — the NAV off your provider's own page,
re-typed every few months — is the supported path, and the only terms involved are your provider's.
`"yahoo:<symbol>"` is offered because it is what actually resolves for most funds, but it calls an
undocumented endpoint whose terms do not cover this use; `finances/NOTES.md` says so plainly, and
the choice is yours to make knowingly rather than by default. Whichever you pick, check it before
trusting it:

```
python3 scripts/finances.py --probe-nav
```

Now build a real snapshot with no credentials at all. `--replace-example` is needed exactly once:
until you pass it, the script refuses to write over the invented household the app ships with, so a
stray run cannot quietly empty the example.

```
python3 scripts/finances.py --no-banks --replace-example
cd finances && python3 -m http.server 8000 --bind 127.0.0.1   # then open localhost:8000
```

`--bind 127.0.0.1` is not decoration. `http.server` listens on every interface by default, and the
file it is about to serve is your own balances, your loans and what your home is worth — on a café,
hotel or office network, anyone on it could simply ask for it.

Your property indexed at the live figure, your cars depreciated, your loans amortised, your funds
priced. No cash, no spending, no card — and the app says so at the top rather than leaving you to
wonder. Get that looking right and the bank setup below is all that is left.

## Step 2 — an Enable Banking application

About twenty minutes, once, on a computer with a browser. A phone cannot do it.

1. Sign up at **enablebanking.com**. Email link, no card.
2. In the control panel, create an **application** in the live (non-sandbox) environment. The free
   tier is production access limited to accounts you link yourself, which is why no eIDAS
   certificate is needed.
3. **Register a redirect address.** Some providers reject a plain `http` one outright. If
   `http://localhost:8765/callback` is accepted, use it and the script below will catch the code by
   itself. If it is rejected, register `https://localhost/callback`, with no port — nothing listens
   there, so after the sign-in the browser shows a "cannot connect" page, and *that failure is the
   finish*: the address bar holds the code, and the script asks you to paste it.
4. **Generate the key yourself**, so the private key never passes through a web page. Choose
   *generate outside the browser*, and:
   ```
   umask 077; mkdir -p ~/.enablebanking
   openssl req -new -x509 -newkey rsa:4096 -nodes -sha256 -days 3650 \
       -keyout ~/.enablebanking/key.pem \
       -out ~/Downloads/enablebanking-public.crt \
       -subj "/CN=my finances"
   ```
   Upload the `.crt`; keep the `.pem`. Note the **application ID** (a UUID).
5. **Link your own accounts in the panel.** Until you do, the application is inactive and even
   listing banks answers `403 Application is not active`. This is *not* the same as requesting
   activation, which is for serving other people and needs a contract you do not want.

## Step 3 — authorise each bank, once

```
pip install 'cryptography>=42'          # the only dependency; it signs the JWT
export ENABLEBANKING_APP_ID='<the UUID>'
python3 scripts/finances.py --aspsps --country NO --key ~/.enablebanking/key.pem
```

That lists every bank on offer in that country. Find yours, and note the name **exactly** as it is
printed — a credit card is often listed under the card's own name rather than the issuing bank's.

Then one command per connection. Each opens a bank sign-in that **the person** completes.
Redirect the output to a file so the session id never reaches your screen or your scrollback:

```
umask 077
python3 scripts/finances.py --connect --key ~/.enablebanking/key.pem \
    --aspsp '<bank name, exactly>' --id bank \
    --redirect https://localhost/callback > ~/.enablebanking/bank.sid

python3 scripts/finances.py --connect --key ~/.enablebanking/key.pem \
    --aspsp '<card name, exactly>' --id card \
    --redirect https://localhost/callback > ~/.enablebanking/card.sid
```

Two things about the paste, if you are on the `https://localhost` path. The **whole** address is
wanted, `?code=` and all, and it must be pasted **into the running script**, not into the shell,
where a shell will eat the `?` and `&`. The code dies within minutes, so copy it the moment the
error page appears.

`--id` is yours to choose: it becomes the source id in the snapshot, and `SOURCE_LABELS` near the
bottom of `scripts/finances.py` turns it into what the app prints. `bank` and `card` are what this
guide assumes.

Each of those files now holds one line — `bank = <session id>`. Step 4 reads them as a single JSON
object in **`~/.enablebanking/sessions.json`**, so build that file now:

```
umask 077
python3 -c 'import json,sys;print(json.dumps(dict(l.strip().split(" = ",1) for f in sys.argv[1:] for l in open(f) if " = " in l)))' \
    ~/.enablebanking/*.sid > ~/.enablebanking/sessions.json
```

which gives `{"bank": "…", "card": "…"}`. One entry is fine if only one bank worked. To check it
without printing a credential, list its keys:

```
python3 -c 'import json,os;print(list(json.load(open(os.path.expanduser("~/.enablebanking/sessions.json")))))'
```

## Step 4 — the three secrets

`gh` must be signed in as the repository owner. Pipe rather than type, so nothing lands in your
shell history:

```
gh secret set ENABLEBANKING_APP_ID      --repo "$REPO" --body "$ENABLEBANKING_APP_ID"
gh secret set ENABLEBANKING_PRIVATE_KEY --repo "$REPO" < ~/.enablebanking/key.pem
gh secret set ENABLEBANKING_SESSIONS    --repo "$REPO" < ~/.enablebanking/sessions.json
```

`gh secret list --repo "$REPO"` should now show all three. Delete `sessions.json` afterwards;
GitHub holds the copy that matters.

## Step 5 — the first real pull

```
gh workflow run refresh-finances.yml --repo "$REPO" -f replace_example=true
gh run watch
```

`replace_example=true` belongs on this run and no other. If the snapshot committed in your copy is
still the example household — because you never committed what Step 1 built locally — the script
refuses to overwrite it without that flag, which is what stops an idle dispatch from emptying the
app. Once a real snapshot is committed, drop the flag; every later run needs nothing.

A green run has committed a real `finances/data/snapshot.json`, and the last step prints one line
per source with its status. The example-data banner is gone and the numbers are yours.

**Do not re-run it to watch it work.** The daily run uses about three calls per account against an
allowance of four, so a second run in the same day is the whole margin and a third starts losing
accounts until midnight. The app carries the last good balance and marks the source stale rather
than dropping the account, so a spent allowance looks like a warning, not like money vanishing.

What the log says, when it does not go green:

| What the log says | What it is |
| --- | --- |
| `missing environment: …` | a secret did not get set |
| `-> 401` | the key or the application id |
| `-> 403 Application is not active` | accounts are not linked in the control panel yet |
| `-> 429 …RATE_LIMIT…` | the four reads a day are spent; it recovers tomorrow |
| `no bank answered` | every session is dead — redo Step 3 |
| `…is still the example data…` | run it once with `-f replace_example=true` |

`python3 scripts/finances.py --probe` prints what the API actually returned, redacted, which is
the fastest way to fix a shape mismatch.

## Step 6 — categories, which is where the last hour goes

`finances/categories.json` turns a transaction's text into a category. What ships matches the
plain-English texts the example uses; **your bank writes something else**. Open the Transactions
pane after the first real run, read what is landing in *Uncategorised*, and paste those strings
into the right rule. First match wins, top to bottom, so specific rules go above general ones.
Editing the file re-categorises everything on the next refresh, past transactions included —
nothing is baked in.

## Step 7 — the clock

`refresh-finances.yml` only ever runs when something asks it to; nothing here runs it on a
schedule by itself, deliberately. Read `scheduler/README.md`, pick a clock, and point it at:

```
https://api.github.com/repos/OWNER/REPO/actions/workflows/refresh-finances.yml/dispatches
```

with a token scoped to **Actions: Read and write** on this repository only, nothing more.
**Once a day**, not hourly — see the rate limit above.

## Step 8 — onto the phone

1. Open the raw address of `zips/finances.zip` in Safari → Share → Snuggery, to install it.
2. In your loop shortcut's Dictionary, add one row: key `Finances`, value the raw address of
   `finances/data/snapshot.json`. A private repository's fetch needs the headers
   `Authorization: Bearer <your read token>` and `Accept: application/vnd.github.raw`.
3. In your rebuild shortcut's Dictionary, add the matching row: key `Finances`, value a Dictionary
   with `job` =
   `https://api.github.com/repos/$REPO/actions/workflows/refresh-finances.yml/dispatches`
   and `data` = the same snapshot address as above.

## Keeping it honest

- **Re-anchor the funds every few months.** Accrued units drift — settlement dates are a
  convention, fees come off somewhere, dividends get reinvested. Paste the real unit counts back
  into `holdings.json`, move `anchorDate` to today, and the drift resets to zero. The Savings pane
  tells you how long it has been.
- **Update a loan's `nominalRate` when the bank changes it**, or the modelled balance walks away
  from the real one. If the bank happens to expose the loan over PSD2, it arrives as an account
  with a negative balance and that real figure wins: set `preferBankBalance` to the account's name.
- **Re-anchor the home from a real valuation** when you get one. An index moves a number; it does
  not know what you did to the kitchen.
- **The history is recomputed from scratch every run, not appended to.** Everything except cash is
  a function of the date, so fixing a wrong anchor fixes the past too. There is no accumulating
  file to corrupt.

## Do not touch

- `finances/app.js`, `style.css`, `index.html` — the app itself. Change the data, not the code.
- `finances/data/snapshot.json` by hand — the next refresh overwrites it.
- The three secrets' values, once set, except by redoing Steps 3 and 4.

## The trap worth knowing about

**A failed fetch is valid JSON too.** An expired token answers with an error envelope, a `200`
with a body that is not your data. The Shortcut will write that over a good snapshot without
complaint. The app checks the shape and says so on screen rather than drawing an empty chart — but
if a dashboard ever looks suspiciously blank, read the last workflow run's final step, which
prints every source and its status.
